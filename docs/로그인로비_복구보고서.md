# 로그인 → 메인 로비 첫 화면 복구 보고서

## 범위

- 작업 브랜치: `issue8`
- 포함: 로그인 Title Spine, 계정 입력/생성 UI, 로그인 성공 후 `Main` 전환, 로비 배경·프로필·4종 재화·설정/로그아웃·하단 3개 메뉴의 리소스 표시
- 제외: 캐릭터 스탠딩, 모집/사도/모험 화면 전환, 실제 플레이 씬, 계정 초기화, 로딩 연출
- 배포 경계: 로컬 학습·비공개 검증용이며 원본 추출 자료는 외부에 업로드하지 않는다.

## 사용한 근거와 생성물

### 로그인

- 원본 근거: `Trickcal_Reference/03_extracted_resources/02_raw_data/Assets/02.resources/00.title/spine/background`
- Unity export 교차 검증: `Trickcal_Reference/03_extracted_resources/01_unity_data/ExportedProject/Assets/02.resources/00.title/spine/background`
- Unity용 생성 복사본: `Assets/Game/Content/UI/Login/Spine/TitleBackground`
- manifest: `Recovery/Manifests/login-resources.json`
- 준비 도구: `Tools/Recovery/Prepare-LoginResources.ps1`, `Tools/Recovery/Recover-LoginResources.py`

원본 `skel/atlas/png`과 ExportedProject 대응 파일의 크기와 SHA-256이 일치함을 먼저 확인했다. 원본 atlas는 `pma:true`이고 프로젝트는 Linear Color Space이므로, 원본은 그대로 보존하고 Unity용 PNG 복사본만 PMA → Straight Alpha로 변환했다. Unity용 atlas 복사본의 PMA 표기도 이에 맞게 `false`로 바꿨다. 원본 GUID는 유지하고 AssetBundle 라벨만 Unity용 `.meta`에서 제거했다.

### 메인 로비

- 사용한 승인 리소스: `Assets/Game/Content/UI/Lobby`의 배경 1개와 UI sprite 14개
- 기존 manifest: `Recovery/Manifests/lobby-resources.json`
- 배치 근거: 기존 프로젝트의 검증 캡처와 `LobbyRoot.prefab`, `PerspectiveUIMgr.prefab`, `MainLobby.unity`의 2560×1440 Canvas 설정

기존 프로젝트의 코드는 이식하지 않고 배치 근거로만 사용했다. 부족한 원본 자료를 이번 단계에서 추가 추출하지 않았으며, 캐릭터 스탠딩은 다음 복구 범위로 남겼다.

## 구현 구조

- `Assets/Game/MainUI/Prefabs/LoginScreen.prefab`
- `Assets/Game/MainUI/Prefabs/LobbyScreen.prefab`
- `Assets/Scenes/Flow/Login.unity`
- `Assets/Scenes/Flow/Main.unity`
- 재생성 Builder: `Assets/Game/App/Editor/FlowSceneBuilder.cs`, `LoginLobbyUIBuilder.cs`
- 캡처 도구: `Assets/Game/App/Editor/LoginLobbyRatioCapture.cs`

`LoginScreenView`와 `LobbyScreenView`는 입력과 표시만 담당한다. 계정 검증, 저장, 세션, 재화 조회, 씬 전환은 기존 `AuthController`, `LobbyController`, `SceneFlowController`에 연결했다. `GameApplication`에는 실행 순서와 중복 인스턴스 방지를 추가해 로그인 → 메인 → 로그아웃 → 로그인 순환에서도 하나의 루트 컨테이너만 유지한다.

하단 모집/사도/모험 버튼은 리소스 확인용으로 표시하되 `interactable=false`로 두었다. 이는 해당 기능을 다른 브랜치에서 구현한다는 확정 범위를 지키기 위한 것이다.

## 검증 결과

### 확인됨

- Canvas 기준 해상도는 원본 prefab/scene 근거와 같은 2560×1440이다.
- Title skeleton은 Spine `4.1.08`이며 `Normal` skin, `Start`, `Idle` animation이 존재한다.
- Title atlas page는 `Title_Background.png`와 일치한다.
- Straight Alpha material은 Linear Color Space에서 Spine material 검사 경고가 없다.
- 로그인 실패 시 계정 생성 UI가 열리고, 신규 계정 생성 성공 시 `Main`으로 이동한다.
- 로비는 저장된 닉네임, 레벨, Gold/Elleaf/Macaron/Stamina를 표시한다.
- 설정 메뉴에서 로그아웃하면 session이 삭제되고 `Login`으로 돌아간다.
- `Tools/check-layers.sh`: 62개 파일, 계층 참조 위반 없음.
- MainUI EditMode: 7/7 통과.
- MainUI PlayMode: 1/1 통과(신규 계정 → 로비 → 로그아웃 전체 흐름).
- 프로젝트 전체 EditMode: 36/36 통과(`Artifacts/SpineRecovery/LoginLobby/all-editmode-results.xml`).
- 프로젝트 전체 PlayMode: 3/3 통과(`Artifacts/SpineRecovery/LoginLobby/all-playmode-results.xml`).
- 캡처: `Artifacts/SpineRecovery/LoginLobby/Captures`의 로그인/메인 16:9·4:3 총 4장.

### 추론

- 로그인 카드의 모양과 문구는 현재 계정 API를 사용할 수 있도록 재구성한 UI다. 원본 로그인 화면과 동일하다고 주장하지 않는다.
- 로비의 상단/하단 배치는 기존 검증 캡처와 원본 prefab의 해상도·앵커를 바탕으로 재구성했다. 개별 픽셀 배치가 원본과 정확히 같다는 근거는 없다.
- `Start` 후 `Idle` 순서는 이전에 검증한 Flow 구현을 재사용한 동작 근거다. 모든 세부 transition timing이 원본과 같다고 확정하지 않는다.

### 미확인

- 원본 로그인 화면의 정확한 입력 UI, 문구, 로고, 사운드 및 전환 timing
- Title 화면의 별도 캐릭터 조합과 완전한 연출
- 플레이어 경험치 다음 레벨 계산식(현재 첫 로비에서는 경험치 fill을 0으로 표시)
- 메인 로비 스탠딩 캐릭터, 상호작용, 사운드, FX
- 모집/사도/모험 버튼의 실제 목적지와 동작

PlayMode 시작 로그에는 이번 범위 밖의 일부 Monster Spine texture가 PMA 설정과 맞지 않는다는 기존 경고가 남아 있다. Title 리소스 자체의 PMA/Linear 경고는 제거됐으며, Monster 경고는 이 변경에서 수정하지 않았다.

## 재현 순서

1. `Prepare-LoginResources.ps1 -Apply`로 source identity, raw/export hash, GUID를 검증하고 Unity용 복사본을 만든다.
2. Unity 6000.3.16f1에서 프로젝트를 임포트한다.
3. `Prepare-LoginResources.ps1 -FinalizeUnityMeta -Apply`로 Unity 정규화 이후 meta와 manifest를 확정한다.
4. `Tools > Trickcal Revive > Flow > Build Login-Main Scenes`를 실행한다.
5. `Login` 씬에서 Play하거나 EditMode/PlayMode 테스트를 실행한다.
6. 화면 비교가 필요하면 `Tools > Trickcal Revive > Flow > Capture Login-Lobby Ratios`를 실행한다.

이 결과는 첫 화면 복구 단위이며 `productionComplete`가 아니다.
