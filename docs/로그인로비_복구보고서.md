# 로그인·메인 로비 복구 보고서

## 범위

- 작업 브랜치: `issue8`
- 이번 변경: 원작 스크린샷을 기준으로 메인 로비의 상단 프로필, 통화 슬롯, 하단 `모집`·`사도`·`모험` 버튼 이미지와 누름 피드백 복구
- 유지한 기존 범위: 로그인, 계정 생성, 로그인 후 `Main` 전환, 설정 메뉴와 로그아웃
- 제외: 모집·사도·모험 목적지 씬 전환, 로비 캐릭터/Spine 배치와 상호작용, 음향·진동·FX
- 배포 경계: 비공개 학습·검증용이다. 추출 원본은 외부에 업로드하거나 공개 배포하지 않는다.

## 원본 보존과 생성 복사본

원본은 `Trickcal_Reference` 아래의 읽기 전용 증거로만 사용했다. Unity에서 쓰는 파일은 다음 스크립트로 별도 생성했으며 원본 파일을 변경하지 않았다.

- 복구 스크립트: `Tools/Recovery/Recover-LobbyUIChrome.py`
- 해시 manifest: `Recovery/Manifests/lobby-ui-chrome.json`
- 생성 Sprite: `Assets/Game/Content/UI/Lobby/Chrome`
- 생성 폰트 복사본: `Assets/Game/Content/UI/Fonts/ONE Mobile POP.ttf`
- 생성 TMP Font Asset: `Assets/Game/Content/UI/Fonts/ONE Mobile POP SDF.asset`

기존 `Recovery/Manifests/lobby-resources.json`은 issue2의 15개 리소스 계약이므로 수정하지 않았다. 이번 세트는 Sprite/Font 9개와 각 `.meta`를 합쳐 manifest 18개 항목으로 분리했다.

## 확인됨

### 리소스

- 기존 스크립트의 넓은 `*MainLobby*` 검색은 `AmeliaR41MainLobby` 아틀라스를 먼저 선택할 수 있었다. 이번 스크립트는 `*-MainLobby-*.png` 형식의 canonical 페이지를 정확히 하나만 허용한다.
- `MainLobby_BtnBg`, `GachaButton`, `HeroButton`, `MainLobby_UserInfoBase`, `MainLobby_LevelBase`는 `MainLobby` SpriteAtlas 직렬화 키와 canonical 페이지를 대조해 복구했다.
- `TopMenu_Base`, `TopMenu_CurrencyBase`는 `CommonIcons` SpriteAtlas 직렬화 키로 복구했다.
- 제공된 스크린샷의 모험 버튼 캐릭터는 raw sprite `MainLobby_BattleBtn_Uros.png`와 일치한다. Unity 복사본은 원본과 바이트 및 SHA-256이 같다.
- 한국어 라벨은 Reference 프로젝트의 `ONE Mobile POP.ttf`를 바이트 단위로 복사해 동적 TMP Font Asset으로 사용한다.

### 배치와 입력 동작

- 원본 `MainLobby.prefab`의 버튼 루트 크기는 `207x252`이다.
- 원본 버튼 입력 컴포넌트에 `BaseScale=(1,1)`, `PressedScale=(0.9,1.2)`, `ReleaseScale=(1.1,0.9)`, `UseReleaseAction=1`, `UseScaled=1`이 직렬화돼 있다.
- 따라서 하단 세 버튼은 선택 상태를 유지하지 않는다. 누르는 동안 세로로 늘어나고 가로로 줄어든 뒤, 손을 떼면 반대 방향으로 튕기고 원래 크기로 돌아온다.
- 원본 `TopCurrencySlot.prefab` 기준 통화 슬롯은 `336x76`, 아이콘은 `90x90` 하단 피벗, 우측 추가 버튼은 `76x76`이다.
- 제공된 스크린샷과 같이 상단 통화는 체력·골드·엘리프 세 슬롯만 표시한다. 기존 Macaron 데이터 API는 호환을 위해 남겼지만 화면에는 만들지 않는다.
- 원본 `TopMenu.prefab`의 프로필 루트 크기 `578x112`를 사용하고 확인된 녹색 `MainLobby_UserInfoBase`를 배치했다.

## 추론

- 원본 Tween 지속시간과 easing 직렬화 자료를 찾지 못했다. 현재 `0.07초 → 0.06초 → 0.09초`의 짧은 unscaled-time 보간은 결정론적 재현값이다.
- 원본에는 여덟 개 하단 메뉴가 있으나 현재 구현 범위는 세 개뿐이므로 중앙 정렬 간격은 제공된 스크린샷과 현재 범위에 맞춘 재구성이다.
- 플레이어 초상은 계정별 동적 데이터가 아직 없으므로 확인된 `HeroButton` 이미지를 녹색 원형 프레임 안의 임시 초상으로 사용한다. 원본 계정 초상 복구물로 취급하지 않는다.
- 현재 배경은 기존 issue2에서 선택한 `Lobby_Default`이며, 제공된 스크린샷의 야외 로비 배경 및 캐릭터 배치는 이번 UI 범위에 포함하지 않았다.

## 재현 순서

1. `Recover-LobbyUIChrome.py --project-root <project> --source-root <reference>`를 실행한다.
2. Unity에서 `Tools > Trickcal Revive > Flow > Build Login-Main Scenes`를 실행한다.
3. EditMode와 PlayMode에서 `TrickcalRevive.MainUI.Tests`를 실행한다.
4. `Tools > Trickcal Revive > Flow > Capture Login-Lobby Ratios`로 세 화면 비율을 다시 캡처한다.

이 결과는 issue8의 로비 UI 복구 단위이며 전체 게임 플레이 복구 완료를 의미하지 않는다.
