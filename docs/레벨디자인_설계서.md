## 1. 전제와 범위

캐릭터 30명과 몬스터 20종이 아직 선정되지 않은 상태다(원본 기획서 28.2장). 특정 자산에 의존하는 실제 수치(캐릭터별 기본 스탯, 스킬 계수, 개별 스테이지 몬스터 배치)는 이 문서의 범위 밖이며, 자산 선정 후 아래 공식에 값을 대입해 채운다.

이 문서가 확정하는 것:
- 레벨 성장 공식 (수식)
- 챕터·스테이지 난이도 곡선 (수식)
- 웨이브 편성 패턴 (규칙)
- 행동력 비용, 보상량 (수식)
- 시간 제한과 난이도의 관계 (가이드라인)

이 문서가 확정하지 않는 것 (후속 작업, §7 참고):
- 캐릭터·몬스터별 실제 기본 스탯 수치
- 몬스터 실제 HP·방어력 (시간 제한 가이드라인의 역산 대상)
- 개별 스테이지의 실제 몬스터 배치 좌표

## 2. 스탯 성장 공식

### 2.1 공식

```text
stat(level) = base_stat × (1 + growth_rate × (level - 1))
```

레벨 1~100 구간에서 선형 성장을 사용한다. 19.1장의 곱연산 레이어(학년 배율 × 카드 배율 × 버프 배율)가 이미 여러 겹이므로, 레벨 성장까지 지수적으로 겹치면 후반 레벨 수치를 통제하기 어렵다. 10.2장의 "무난한 난이도" 목표와도 선형 성장이 더 잘 맞는다.

### 2.2 적용 대상 스탯

| 스탯 | 레벨 성장 적용 | growth_rate |
|---|---|---:|
| `max_hp` | O | 0.03 |
| `attack` | O | 0.03 |
| `defense` | O | 0.03 |
| `max_sp` | X | - |
| `attack_speed` | X | - |
| `attack_range` | X | - |
| `move_speed` | X | - |
| `sp_regen` | X | - |
| `active_skill_cooldown` | X | - |

- HP·공격·방어 3개 스탯만 레벨 성장을 적용하고, 셋이 동일한 `growth_rate`를 공유한다.
- 역할 차별화(탱커는 HP 위주, 딜러는 공격 위주)는 성장률이 아니라 `character_master.base_stats_json`의 캐릭터별 기본값 차이와 16.4장 6학년 역할 특화 배율로 표현한다.
- 나머지 6개 스탯은 레벨에 따라 변하지 않는 캐릭터 고유값이며, 카드·버프로만 일시적으로 변동한다.
- `growth_rate = 0.03`은 레벨 100 도달 시 레벨 1 대비 약 `1 + 0.03 × 99 ≈ 3.97`배가 되는 잠정값이다. 캐릭터·몬스터 스탯이 확정된 뒤 전투 시뮬레이션(§7, 29장 12번)으로 검증하고 조정할 수 있다.

### 2.3 저장 위치

이 공식의 파라미터(`growth_rate`, 적용 대상 스탯)는 코드에 하드코딩하지 않고 `economy_master.growth_table`(`growth_type: character_level`)에 데이터로 저장한다. 상세 필드는 `DB_설계서.md` §4.5.2 참고.

## 3. 챕터·스테이지 난이도 곡선

### 3.1 권장 레벨 공식

```text
global_stage_index = (chapter_no - 1) × 10 + stage_no   (1~100)
recommended_level  = min(99, global_stage_index)
```

스테이지 1개당 권장 레벨이 정확히 1씩 오른다.

| 챕터 | 스테이지 범위(전역) | 권장 레벨 범위 |
|---:|---|---|
| 1 | 1~10 | 1~10 |
| 2 | 11~20 | 11~20 |
| ... | ... | ... |
| 10 | 91~100 | 91~99 (마지막 스테이지도 99에서 유지) |

### 3.2 몬스터 레벨

```text
monster_level = recommended_level
```

몬스터 레벨은 스테이지 권장 레벨과 동일하게 맞춘다. 난이도 차이는 레벨 격차가 아니라 몬스터 수(§4.1)와 등급 배율(정예 1.2배/보스 1.5배, `combat_master.common_config`)로 만든다. 이렇게 하면 "권장 레벨보다 몬스터 레벨이 왜 높은가/낮은가"에 대한 별도 설명이 필요 없어진다.

## 4. 웨이브 편성 패턴

모든 스테이지는 고정 5웨이브(10.1장)이며, 아래 규칙으로 몬스터 수·등급을 산출한다. 개별 스테이지를 손으로 배치하지 않고 공식으로 채운 뒤, 챕터 보스만 예외적으로 지정한다.

### 4.1 웨이브별 기본 마리 수

| 웨이브 | 마리 수 |
|---:|---:|
| 1 | 2 |
| 2 | 3 |
| 3 | 3 |
| 4 | 4 |
| 5 | 4 |

이 마리 수는 스테이지 난이도(챕터)와 무관하게 모든 스테이지에 공통 적용된다.

### 4.2 정예 등장 규칙

| 챕터 구간 | 정예 등장 |
|---|---|
| 1~3 | 없음 (전부 일반 등급) |
| 4~7 | 웨이브 4~5에 정예 1마리 포함 |
| 8~10 | 웨이브 3~5에 정예 1~2마리 포함 |

### 4.3 보스 등장 규칙

보스 등급 몬스터는 **각 챕터의 마지막 스테이지(stage_no = 10)의 웨이브 5**에만 등장한다. 전체 100스테이지 중 챕터 보스는 10마리뿐이며, 나머지 90개 스테이지는 일반/정예 조합으로만 구성된다.

### 4.4 몬스터 속성 배분

웨이브 내 몬스터는 20종 몬스터 풀(5속성 × 4종)에서 스테이지 순서에 따라 로테이션한다. 배치는 스테이지 제작 시 한 번 고정하며, 재입장 시 바뀌지 않는다(10.1장 MasterData 원칙과 동일).

## 5. 행동력(스태미나) 비용

```text
stamina_cost = 6   (전 스테이지 공통)
```

챕터·스테이지 구분 없이 모든 스테이지가 동일한 스태미나 비용을 사용한다. 스태미나는 7.1장 기준 20초당 1 회복되므로, 1스테이지 = 약 2분 회복분에 해당한다.

## 6. 보상 공식

### 6.1 반복 클리어 보상 (골드·경험치)

```text
gold_reward = 100 × recommended_level
exp_reward  = 50 × recommended_level
```

권장 레벨이 높을수록(후반 스테이지일수록) 스태미나 비용은 동일해도 보상은 비례해서 늘어나, 후반 스테이지를 반복하는 유인이 생긴다.

### 6.2 첫 클리어 보너스

```text
first_clear_bonus_gold = gold_reward × 5
first_clear_bonus_exp  = exp_reward × 5
```

첫 클리어 시 반복 보상과 별도로 1회만 추가 지급한다.

### 6.3 별 보상

- 별 1개당 전용 조각 또는 공통 조각 1~2개를 지급한다. 정확한 종류·수량은 스테이지 제작 시 개별 지정한다(11장 별 조건과 동일하게, 재입장 시 바뀌지 않음).
- **챕터 누적 별 보상**은 챕터 내 별 30개(10스테이지 × 3별) 만점을 향해 **10개 / 20개 / 30개 3단계**로 나눠 각 단계 도달 시 1회씩 지급한다. 단일 지급이 아니라 3회 분할 지급이다.

### 6.4 예시 (챕터 10, 스테이지 100)

`recommended_level = 99` 기준:
```text
gold_reward = 9,900
exp_reward  = 4,950
first_clear_bonus_gold = 49,500
first_clear_bonus_exp  = 24,750
```

이 수치는 26장(영구 성장)의 레벨업 비용표, 6.3장(재화 교환 비율)과 함께 역산해 최종 밸런스를 조정한다(§7).

## 7. 적 HP와 전투 제한 시간의 관계 (가이드라인)

캐릭터·몬스터 자산이 아직 없어 실제 몬스터 HP 공식은 만들지 않는다. 대신 검증 목표만 확정한다.

```text
목표 클리어 시간 = 전투 제한 시간(80초)의 50% 이내
= 웨이브당 목표 40초 이내
```

- 각 웨이브의 "몬스터 총 유효 HP"(방어력 반영 실효치)는, 해당 스테이지 권장 레벨의 사도 파티가 40초 안에 처치 가능한 수준으로 몬스터 스탯을 역산해서 맞춘다.
- 이 역산은 캐릭터·몬스터 스탯이 확정된 뒤 전투 시뮬레이션으로 검증한다(원본 기획서 29장 12번 "전투 시뮬레이션으로 카드 경제와 제한 시간을 검증").
- 정예(1.2배)·보스(1.5배) 배율이 적용된 개체는 목표 시간에서 비례 여유를 두고 검증한다.

### 7.1 실제 구현된 전투 진행 방식 (2026-07-19 추가)

이 장의 시간 목표(§7)는 그대로 유지되지만, 실제 클리어 시간에 영향을 주는 진행 방식 두 가지가 이번 세션에 확정됐다. 상세 동작은 `docs/전체_기획서.md` §4를 참고한다.

- **준비 40초는 배속과 무관하게 항상 1배로 흐른다.** 배속(x1/x2/x3) 버튼은 전투 80초 구간에만 적용된다. 따라서 "웨이브당 목표 40초 이내"(§7)는 전투 구간 기준이며, 준비 구간 40초는 이 목표 시간 계산에 포함하지 않는다.
- **몬스터 총 유효 HP를 역산할 때는 제자리 딜링이 아니라 사거리·이동 기반 전투를 전제한다.** 사도가 타겟이 사거리 밖이면 접근해야 공격이 시작되므로, 초반 접근 시간만큼 실질 딜링 시간이 40초보다 짧아진다. §7의 역산·시뮬레이션 단계(§8-4)에서는 이 접근 시간을 여유값으로 반영해야 한다.

## 8. 후속 작업 (자산 선정 이후)

이 프레임워크를 실제 100스테이지에 대입하려면 다음이 선행되어야 한다 (원본 기획서 29장 순서와 동일):

1. 캐릭터 30명, 몬스터 20종 에셋 후보 선정 (28.2장)
2. 속성·역할·최초 성급 배분표 작성
3. 캐릭터·몬스터 `base_stats_json` 기준값 확정 — §2 공식의 `base_stat`에 대입
4. §7 가이드라인에 따라 몬스터 HP·방어력 역산 및 전투 시뮬레이션 검증
5. §4 규칙에 따라 100스테이지 웨이브 실제 몬스터 배치(`stage_master.waves_json`) 생성
6. 챕터 보스 10마리 개별 지정
7. §6 공식으로 산출한 보상량을 `stage_master.rewards_json`에 실제 반영
8. 26장 레벨·성급·스킬 성장 비용표(28.4장 미정 항목)를 §2 성장 공식과 정합성 있게 작성
